# Kimi K3，讲给懂统计学的人听

> 本文是 [`kimi-k3-explained.md`](kimi-k3-explained.md) 的中文翻译。以英文原稿为准；如有出入，以原文为准。

是
[`docs/whiteboards/k3-architecture.excalidraw`](whiteboards/k3-architecture.excalidraw)
那面白板的配套说明。写给懂统计、但有一阵没碰深度学习的人。每个概念都锚定到你已经
在用的东西——加权平均、在线估计器、混合模型、提升、记忆化——于是行话不再是行话。

**一段话的思维模型。** 注意力是对词做加权平均；KDA 把它变成*移动*平均（线性成本，
不是 n 平方）；AttnRes 让层像提升阶段回溯那样复用更早的层；MoE 是一个稀疏混合模型，
每个输入只评估少数几个组件；serving 纯属工程——把读和写分开、把上下文记忆化，让重复
的循环变便宜；而价格标签不过是把这些省下来的钱传递出去。

## 白板，逐节讲

### 1. MoE——一个 2.8T 的大脑，一次只醒 ~50B

**基本思路。** 不做一个巨型网络，MoE（Mixture of Experts，专家混合）放很多小的「专家」
子网络（896 个），外加一个*路由器*，对每个词挑出少数最相关的专家（16 个）。只有这些
被激活。

**统计类比。** 这是一个**带门控函数的混合模型**——正是 Jacobs & Jordan 在 90 年代初的
专家混合思路：一个门给每个输入指派组件，每个组件是它自己的小回归。变化在于*稀疏性*
——你只评估**top-k 组件**，不是全部。就像一个跳过每一个责任可忽略的组件的混合模型。

**K3 怎么做。** 2.8T *拥有的*总参数，但每个 token 只有 ~50B *活跃*（896 里的 16 个）。
「Stable LatentMoE」= 路由在压缩（latent）空间里做，并调得不会晃。「Quantile Balancing」
= 保持组件使用均匀，这样没有专家过劳、也没有专家死亡（避免退化混合的失败模式）。

> 说：「*拥有整栋豪宅，但每个客人只点亮一间房——前沿的规模，中档的运行成本。*」

### 2. Attention → KDA（Kimi Delta Attention）

**基本思路。** 对每个词，注意力问「其他每个词对我有多相关？」，把相关度变成权重，再取
它们值的加权和。

**统计类比。** 那是一个**核加权估计器**（Nadaraya–Watson）：权重是相似度核，输出是加权
均值。要得到权重，它比较*每一对*词——一个 n×n 矩阵，像完整的 Gram / 成对距离矩阵。
n 个词 → n 平方的工作量。**词翻倍 → 工作量 4 倍。** 到 1M 词那是致命的。（这个
「n 平方」正是长上下文昂贵的全部原因。）

**K3 怎么做。** KDA 用**递推**算出同样的东西，而不是重新算。你绝不会在新数据点到来时
重新求和所有数据来取均值——你保持一个**移动均值并更新它**（Welford）、一个
**指数加权移动平均**、或一个**递推最小二乘 / Kalman** 更新。KDA 带着一个小的**状态矩阵
（充分统计量）**，一个 token 一个 token 地更新它——线性成本，不是平方成本。那个
**「Delta」** 就是 delta 规则：按修正量更新——擦掉过期的关联、写下新关联——就像在 (x, y)
对流入时在线更新回归系数。

那些粉色的**「full attention checkpoint」**行：递推估计器会随着近似误差累积而漂移，所以
每隔几层 K3 做一次*精确*的完整注意力来重新锚定——就像定期在所有数据上重新拟合来修正
漂移。

> 说：*「KDA 就是把注意力当移动平均来算，而不是每一步都重新求和所有东西。」*

### AttnRes（Attention Residuals，注意力残差）

**基本思路。** 深层网络堆层。一个**残差连接**让每层输出 `input + f(input)`——它保持一个
累加和，每层加一个*修正*。

**统计类比。** 那就是**梯度提升**：每个阶段拟合剩下的（残差），你再把贡献加起来。正是
它让你堆 100 层而信号不退化。标准残差是一阶的——第 *k* 层只建在第 *k-1* 层上
（类 Markov：每个状态只依赖前一个）。

**K3 怎么做。** AttnRes 让后面某层取**所有**更早层的*可学习的加权组合*，而不只是紧挨着
的前一层——它*在深度上做注意力*。把它想成对之前所有提升阶段做回归，而不是只对最近
一个，一个可学习的、复用任何有用早期特征阶段的混合。

> 说：*「AttnRes = 每层可以复用任何更早层的成果，而不只是它正上方那一层。*」

### 3. Serving——为循环而生

完全不是建模——这是运行已训练模型的*工程*。

**两个画像相反的两阶段。**
- **Prefill（预填充）** = 一次读你整个 prompt（所有输入 token 并行）→ 计算密集、
  吞吐型任务。
- **Decode（解码）** = 一个 token 一个 token 地写答案 → 顺序、延迟受限。

这两者就像夜间的批处理任务对比实时的 web 请求。**Disaggregated inference（分离式推理）**
= 在*分开的机器池*上跑它们，各自为各自的任务调优（和把重型 ETL 与低延迟查询服务分开
是同一个直觉）。

**Cache = 充分统计量的记忆化。** 生成时，模型存下它已经处理过的 token 的表示
（keys/values）——一个 **KV 缓存**——这样就不用重算。就是**记忆化**：对已经见过的数据，
别重算一个统计量。

**为什么对 agent 重要。** agent 循环每次迭代几乎重发*相同*的上下文。几乎全部已缓存 →
一个**缓存命中** → 你付约 1/10（每百万 token $0.30 对 $3）。K3 被工程化得让重复的 agent
循环变便宜。

> 说：*「把读和写跨机器分开，而且永远不要重算你已经见过的上下文。*」

### 4. 价格标签（$/M token）

**基本思路。** 定价按**每百万 token** 报价（一个 token 大约 3/4 个词），分成*输入*
（你发的）和*输出*（它生成的）。这里 K3 在两者上都比 Opus 4.8 / GPT 5.5 便宜，而且
即使在 1M 上下文价格也保持平坦。

**统计类比。** 把它想成**每次观测的边际成本**。三个更早的设计选择各自压低了那个边际
成本，价格标签不过是把这些省下来的钱传递出去：
- MoE → 每个 token 只有 ~2% 的参数在算（每个 token 的*算力*便宜）。
- KDA → 注意力是线性的，所以多一个 token 的边际成本不会随上下文增长而爆炸（*这就是
  为什么价格在 1M 范围内平坦*——没有 n 平方惩罚）。
- Cache → 重发的上下文是缓存命中，所以 agent 循环里*有效*输入价格塌到 $0.30。

所以卡片上的数字不是随便的——它们是稀疏 + 线性注意力 + 记忆化的直接财务影子。

> 说：*「又便宜又平坦，因为每个额外 token 的边际成本被三种不同的方式工程化地压了下去。*」

## 语言模型简史

整个领域就是同一个问题，每个时代答得更好一点：**给定前面的词，预测下一个词。**

### Bag-of-words（词袋）
**思路。** 数哪些词出现；忽略顺序。**统计类比。** 一个多项式 / 词频向量——token 的
直方图。「not good」和「good not」完全一样，因为直方图没有顺序。
> 说：*「抓住了主题，丢了含义。*」

### LSTM
**思路。** 从左到右读，边走边携带一个记忆。**统计类比。** 序列上的一个
**状态空间模型 / 递推滤波器**——每步更新的隐藏状态（Kalman 风格）。两个缺陷：顺序
（慢），而且状态在长间隔上衰减（忘了开头）。
> 说：*「一个有短期记忆的读者——就是你们造的那种——但又慢又健忘。*」

### Attention（2017）——转折点
**思路。** 不做移动状态，而是一次看*所有*词并权衡什么要紧。**统计类比。** 第 2 节的
核加权平均——但整个序列上并行计算，所以没有顺序瓶颈、也不会忘开头。
> 说：*「突破——整个演讲都挂在这一个想法上。*」

### Transformer
**思路。** 把注意力堆成很多层。**统计类比。** 把加权平均操作和残差（提升）连接深度地
组合起来。是架构，不只是那个小技巧。
> 说：*「注意力是引擎；Transformer 是整辆车。*」

### LLM
**思路。** 拿一个 Transformer，把它做到巨大，在互联网上训练它预测下一个词。
**统计类比。** 对 next-token 分布在荒谬的规模上做最大似然拟合——而通用技能（写作、编程、
推理）从那个单一目标*涌现*出来。
> 说：*「这就是 ChatGPT / Claude / Kimi——你真正在用的那个东西。*」

### 成本墙
**思路。** 规模不是免费的。**统计类比。** 两个成本：参数太多跑不起，以及注意力的
**n 平方**——词翻倍，工作四倍（第 2 节）。那是长上下文上隐藏的价格标签。
> 说：*「一个更大、更长记忆的模型本应负担不起的原因。*」

### Kimi K3
**思路。** 用三个技巧*击穿*那堵墙的 Transformer/LLM 思路。**回顾。** MoE（稀疏混合 →
便宜算力）、KDA（移动平均注意力 → 干掉 n 平方）、FP4（低精度数字 → 小 4 倍）。每一个
攻墙的一部分。
> 说：*「前沿规模、百万词记忆，但定价跑得便宜——这就是新东西。*」

## 术语表——每个缩写和它的统计孪生

| 术语 | 白话含义 | 统计孪生 |
|---|---|---|
| **MoE** | 很多小专家，每个词只有少数几个激活 | 稀疏混合模型 + 门控（top-k 组件） |
| **active vs total params** | 拥有 vs 每个 token 实际在算 | 完整模型 vs 你评估的组件 |
| **Attention** | 对所有词做加权回看 | 核加权平均（Nadaraya–Watson） |
| **n-squared** | 每个词和每个词比较 | 完整 Gram / 成对矩阵；2× 数据 → 4× 工作 |
| **KDA** | 通过移动状态做线性注意力 | 在线估计器（Welford / EWMA / RLS）+ delta 规则 |
| **Residual** | 每层之后把输入加回来 | 梯度提升（逐阶段修正之和） |
| **AttnRes** | 层复用任何更早层，不只是最后一层 | 对所有先前阶段回归，可学习混合 |
| **Gated MLA** | 压缩 KV 缓存 | 低秩 / PCA 式降维，可学习开关 |
| **SiTU** | 一个激活函数 | 单元内部的非线性 / 连接函数 |
| **MXFP4 / MXFP8** | 用 4 / 8 bit 存数字 | 降低精度——保留 2 位有效数字，不是 8 位 |
| **QAT** | 训练时意识到低精度 | 在知道测量被粗分箱的情况下拟合模型 |
| **Per-Head Muon** | 训练优化器，逐注意力头 | 更新权重的求解器（就像你的拟合例程） |
| **prefill / decode** | 读 prompt / 写答案 | 批处理任务 vs 实时顺序请求 |
| **KV cache / cache-hit** | 复用已见 token 的活 | 充分统计量的记忆化 |
| **context window** | 一次读多少（1M ≈ 数千页） | 估计器一次通过的样本量 |

6.3x / 25% / 2.5x 这些数字是**厂商声明**，来自 Moonshot 自己的博客；开放权重到
2026-07-27 才放出，所以还没人独立验证过。Opus 和 Fable 的内部细节未公开，所以「vs」
